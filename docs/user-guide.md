# cereals 使用指南

> **这是一个 vibecoding 项目，主要通过 AI 辅助编码构建。介意勿用。**
>
> **本项目面向在本地电脑通过 kubeconfig 连接远端 Kubernetes 集群的运维人员、开发者和集群管理员。**

本文说明 cereals 1.0.0 的使用方法。安装包入口见 [项目首页](../README.md)，源码运行方法见 [本地开发与构建](development.md)。

## 连接前准备

准备能够访问远端集群的 kubeconfig。你的电脑需要能解析并连接其中的 API Server 地址；如集群位于内网，请先连接相应网络或 VPN。

应用使用 kubeconfig 中配置的身份，权限由集群 RBAC 控制。证书、令牌和外部认证插件需要在本机有效；使用认证插件时，确保插件已安装且可从应用运行环境找到。

## 导入与连接集群

1. 打开「集群连接」，选择「导入 kubeconfig」或「选择配置文件」；也可读取 `~/.kube/config`。
2. 检查导入的 Context 列表，确认集群地址、命名空间及身份。
3. 点击目标 Context 的连接按钮。若需要运行外部认证插件，确认其命令和来源后再授权。
4. 连接后，通过顶部的集群选择器切换操作目标，并检查命名空间筛选。

可以导入多个配置文件，也可同时连接多个 Context。设置默认集群后，应用启动时会尝试连接；只有一个集群时会自动将其设为默认。断开某个集群时，该连接下的 Watch、终端、日志和端口转发等会话会被清理。

## 浏览与编辑资源

在侧栏选择工作负载、服务与网络、存储、配置、自定义资源等分类，或使用资源浏览器查看集群发现的资源类型。

- 命名空间和标签筛选用于缩小查询范围，名称搜索只过滤当前页。
- 资源列表支持手动刷新和按需开启实时更新。
- 无权列出 Namespace 时，可以手动输入命名空间；资源本身仍需相应权限。
- 常用资源提供可视化表单，复杂配置及 CRD 保留 YAML 编辑入口。

创建或修改资源时，先查看服务端预检结果和 Diff，再确认提交。表单会保留未展示的字段，但仍应检查最终差异，尤其是删除字段、替换 Pod 模板和涉及持久化存储的修改。

遇到资源版本冲突时，保留草稿、重新读取资源并核对差异后重试。请求提交成功表示 API Server 已接受操作，工作负载是否完成发布、PVC 是否完成扩容，还需查看后续状态和事件。

删除、节点排空、回滚等操作前，请再次核对集群、命名空间和资源名称。节点排空后的解封需要单独执行。

## Pod 日志、终端与文件传输

在 Pod 或工作负载详情中选择目标 Pod 和容器，再打开日志、终端、文件传输或端口转发入口。多个会话各自显示操作目标。

| 操作     | 使用说明                                                                      |
| -------- | ----------------------------------------------------------------------------- |
| 日志     | 可选择容器、尾部记录、时间范围及上一次运行日志，支持跟随、暂停和导出          |
| 终端     | 使用容器内已有的 Shell，默认 `/bin/sh`；没有 Shell 的容器无法直接打开交互终端 |
| 文件传输 | 支持单文件上传与下载，需要容器内提供传输所需工具；不支持目录批量传输          |
| 端口转发 | 仅支持 TCP，本地监听地址为 `127.0.0.1`，可指定本地端口或自动分配              |

日志、Exec 和端口转发需要对应的 Kubernetes 子资源权限。会话缓冲有上限；日志视图不保证无限保留历史，重要内容请及时导出。关闭会话、断开集群或退出应用会释放相应资源。

## 配置与数据

应用保存 kubeconfig 文件路径、默认连接与界面设置，不复制 kubeconfig 凭据。请保留原始配置文件和其引用的证书、认证工具；移动或删除这些文件可能导致连接失败。

默认设置位于系统用户配置目录下：

| 平台    | 新安装默认目录                           |
| ------- | ---------------------------------------- |
| macOS   | `~/Library/Application Support/cereals/` |
| Windows | `%APPDATA%\cereals\`                     |

配置目录按以下优先级选择：

1. 环境变量 `CEREALS_CONFIG_DIR`。
2. 兼容旧版的环境变量 `CREALS_CONFIG_DIR`。
3. 已存在的 `cereals` 目录。
4. 已存在的旧 `creals` 目录。
5. 使用新的 `cereals` 目录。

旧配置不会自动搬移或删除。Secret 默认隐藏，显式查看或编辑时应注意屏幕与剪贴板中的敏感内容；日志、终端输出和 YAML 草稿不会作为普通界面设置持久化。

## 托盘与退出

托盘菜单可以显示或隐藏主窗口、查看连接状态、设置关闭窗口后是否继续运行，以及检查更新。

启用关闭到托盘后，关闭主窗口不会结束应用，后台日志、终端、端口转发和 Watch 仍可能运行。需要完全退出时，选择「退出 cereals」；macOS 也可使用 `⌘Q`。尚未保存的编辑草稿应在退出前自行保存。

## 软件更新

发行构建启动后及运行期间会定时检查本仓库的正式 Release，也可以手动检查更新。下载通过校验后，点击「重启并应用」（`Restart & Apply`）完成升级。

macOS 应从已安装的 `cereals.app` 启动，不要从只读 DMG 中执行更新。开发构建、macOS 裸可执行文件和 Linux 构建不启用更新。尚未接入更新器的旧 creals 版本，需要先手工安装 cereals 1.0.0。

## 常见问题

**连接超时或无法解析集群地址**：检查本机网络、DNS、VPN 和 kubeconfig 中的 API Server 地址。应用的网络请求从本机发出。

**认证失败或认证插件不可用**：检查 kubeconfig 引用的证书、令牌与插件，确认插件在本机可执行。应用不会替你生成集群凭据或提升权限。

**显示权限不足**：确认当前 Context 的身份和目标命名空间，向集群管理员申请具体操作所需权限。某个列表不可见不一定意味着其他资源也不可访问。

**看不到 CPU 或内存用量**：确认集群已安装并正常运行 Metrics Server，且当前身份可以读取对应指标 API。这里显示当前用量，不提供历史监控。

**没有更新提示**：相同版本和更低版本不会触发升级；只有发布了匹配当前系统与架构的更高稳定版本才可升级。网络或附件校验问题可通过手动检查查看错误。

仍无法解决时，请在 [Issues](https://github.com/cereals-af/cereals-desktop/issues) 提供版本、环境与复现步骤，并先移除日志、截图及配置中的敏感内容。
